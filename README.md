# ion-concentration-app-frontend

Фронтенд для лабораторных по РИП. Тема — Расчет концентрации ионов в растворе после смешивания.
Растворы можно листать лентой и искать по молярной концентрации. Бэкенд (REST API на NestJS) лежит в [ion-concentration-app-backend](https://github.com/locos1k/ion-concentration-app-backend).

В этой ветке (ЛР6) SPA на **React**, **TypeScript** и **Vite** подключено к бэкенду. Состояние хранится в
**Redux Toolkit**, запросы к растворам идут через **Axios**, сгенерированный из Swagger клиент и **redux-thunk**
(`createAsyncThunk`), вход и выход — обычным `axios` без thunk. Есть два интерфейса: гость и создатель,
между ними переключает кнопка «Вход»/«Выход». Если бэкенд недоступен, гость видит данные из mock.
`React.Context`, `useReducer` и `localStorage` не используются. Интерфейс рассчитан на вертикальный экран
телефона: на компьютере приложение показывается узкой колонкой (375 px) по центру.

## Запуск

Нужны PostgreSQL, Redis и MinIO из `docker compose` бэкенда. Бэкенд запускается на порту **8000**
(порт 3000 занимает фронтенд), а ссылки на картинки и видео отдаются относительными, чтобы они шли через прокси:

```bash
cd ../ion-concentration-app-backend
docker compose up -d
PORT=8000 MEDIA_BASE_URL=/solution-assets npm run start:dev
```

Фронтенд:

```bash
npm install
npm run dev
```

Приложение откроется на `http://localhost:3000`. Другие команды:

- `npm run generate-api` — сгенерировать `src/api/Api.ts` из Swagger бэкенда (бэкенд должен быть запущен)
- `npm run build` — проверка типов и сборка в `dist/`
- `npm run lint` — проверка кода (oxlint)

### Прокси

Браузер обращается только к `http://localhost:3000`, поэтому CORS не нужен. Vite перенаправляет запросы
([vite.config.ts](vite.config.ts)):

| Путь | Куда | Что |
|---|---|---|
| `/api/*` | `http://localhost:8000` | REST API бэкенда, кука `sessionId` остаётся на одном адресе |
| `/solution-assets/*` | `http://localhost:9000` | изображения и видео из MinIO |

## Страницы

В нижнем меню четыре пункта: **Лента**, **Добавление**, **Плитка**, **Вход**. Гостю «Добавление» недоступно
(пункт приглушён). После входа «Вход» заменяется на **Выход**. Любой неизвестный адрес ведёт на ленту.

| Страница | Адрес | Доступна | Описание |
|---|---|---|---|
| Лента | `/solutions`, `/solutions/:id` | гость, создатель | Раствор с заданным `id`, без `id` — первый |
| Плитка | `/solutions/list` | гость, создатель | Каталог растворов с фильтром |
| Добавление | `/solutions/draft` | создатель | Создание черновика и публикация |
| Вход | `/login` | гость | Аутентификация |

### Лента

Видео раствора на весь экран (автозапуск, без звука, по кругу), поверх него:

- **Название** и **описание**. Длинное описание обрезано, кнопка **Ещё** раскрывает его целиком, **Свернуть** сворачивает обратно.
- **Лайк** — иконка и число лайков. Создатель ставит и снимает лайк нажатием (кнопка подсвечивается белой рамкой, если лайк поставлен), гость видит только число.
- **Следующий** — кнопка со стрелкой, запрашивает у бэкенда следующий раствор (`next=true`). После последнего снова первый.
- **pH** и **моль/л** — круглые бейджи.

Если раствор с таким `id` не найден, показывается «Раствор не найден».

### Плитка

- **Фильтр по молярной концентрации** — два ползунка (0–0,25 моль/л, шаг 0,01). Значения хранятся в Redux и не
  сбрасываются при переходе на другие страницы. Запрос на сервер уходит только по кнопке **Найти**.
- **Карточки** в два столбца: картинка, название, количество лайков, молярная концентрация. Клик по карточке открывает ленту с этого раствора.
- **Удалить** — кнопка на карточке, видна создателю только на его растворах (`isCreator = 1`). Удаление мягкое.
- При выходе фильтр сбрасывается.

### Добавление

Страница создателя. Что показывается, зависит от наличия черновика (его запрашивает бэкенд):

- Черновика нет: поля **Изображение** и **Видео** (выбор файла, превью обновляется сразу), поле **Название вещества**
  (до 70 символов) и кнопка **Далее**. По ней создаётся черновик, файлы уходят в MinIO.
- Черновик есть: превью файлов из MinIO, название только для чтения, поля **Описание** (до 500 символов),
  **Молярная концентрация** (0–99,999) и **pH** (0–14) и кнопка **Опубликовать**. После публикации открывается лента с этим раствором.

Гостя с этой страницы перенаправляет на «Вход». Ошибки сервера (400, 401, 409) показываются над формой.

### Вход

Поля **Логин** и **Пароль**, кнопка **Войти**. При успехе сервер ставит `HttpOnly`-куку `sessionId`, приложение
переходит в интерфейс создателя и открывает плитку. При неверных данных под формой показывается «Неверный логин или пароль».
**Выход** (кнопка в меню) отправляет запрос на сервер и возвращает интерфейс гостя.

Состояние «гость/создатель» хранится только в Redux, то есть в оперативной памяти. По **F5** интерфейс
сбрасывается в гостя, при этом кука `sessionId` остаётся в браузере (вкладка Application), а `localStorage` не используется.

### Спиннер

Пока выполняется запрос, поверх экрана показывается спиннер, а кнопки блокируются.

### Изображение и видео по умолчанию

Если у раствора нет картинки или видео (поле пустое) либо файл по ссылке не загрузился, показываются
`public/img/default-solution.PNG` и `public/img/default-solution.mp4`. Это работает и на плитке, и в ленте, и на странице добавления.

## Запросы к бэкенду

Всего 9 запросов, все через Axios.

| № | Запрос | Как вызывается | Где |
|---|---|---|---|
| 1 | `GET /api/solutions` | thunk `fetchSolutions` | `src/store/thunks/solutions.thunks.ts` |
| 2 | `GET /api/solutions/feed[/:id]` | thunk `fetchSolutionFeed` | то же |
| 3 | `GET /api/solutions/draft` | thunk `fetchSolutionDraft` | то же |
| 4 | `POST /api/solutions` | thunk `createSolutionDraft` | то же |
| 5 | `PUT /api/solutions/:id/publish` | thunk `publishSolution` | то же |
| 6 | `DELETE /api/solutions/:id` | thunk `deleteSolution` | то же |
| 7 | `POST /api/solutions/:id/like` | thunk `likeSolution` | то же |
| 8 | `POST /api/auth/login` | `axios.post` в компоненте | `src/pages/SolutionsLoginPage.tsx` |
| 9 | `POST /api/auth/logout` | `axios.post` в компоненте | `src/components/SolutionsNavbar.tsx` |

Регистрация в этой лабораторной не делается.

Методы 1–7 вызывают сгенерированный клиент (`api.solutions.getSolutionsList`, `getSolutionFeed`, `getSolutionFeedById`,
`getSolutionDraft`, `createSolutionDraft`, `publishSolution`, `deleteSolution`, `likeSolution`). Клиент создаётся
командой `npm run generate-api` ([scripts/generate-api.mjs](scripts/generate-api.mjs)) из `http://localhost:8000/api/docs-json`,
названия методов задаются по теме в том же скрипте.

Если бэкенд недоступен (нет ответа или 502/503/504 от прокси), список и лента берутся из mock (`src/modules/solutions.mock.ts`).
Ошибки сервера (401, 404 и т. д.) в mock не превращаются. Ответ 401 сбрасывает интерфейс создателя в гостя.

## Состояние (Redux Toolkit)

Хранилище `src/store/store.ts`, типизированные хуки `useAppDispatch`, `useAppSelector`, `useAppStore` в `src/store/hooks.ts`.

| Слайс | Что хранит |
|---|---|
| `solutions` | карточки плитки, значения фильтра `min` и `max`, флаги `loading`, `loaded`, `isMock` |
| `feed` | текущий раствор ленты, `notFound` |
| `draft` | черновик создателя, `errorStatus` |
| `user` | `isAuthenticated`, `userId`, `username`; действия `setUser`, `clearUser` (вход и выход без thunk) |

## Что где лежит

- `src/main.tsx` — точка входа, подключает `Provider` и стили
- `src/SolutionsApp.tsx` — роутинг, страница «Добавление» закрыта для гостя
- `src/SolutionsLayout.tsx` — общая оболочка: меню и спиннер
- `src/Routes.ts` — адреса и подписи пунктов меню
- `src/pages/` — страницы: `SolutionsFeedPage`, `SolutionsGridPage`, `SolutionsAddPage`, `SolutionsLoginPage`
- `src/components/` — `SolutionCard`, `SolutionsFilter`, `SolutionDescription`, `SolutionVideo`, `MediaPreview`, `SolutionsNavbar`
- `src/store/` — хранилище, слайсы и thunk
- `src/api/` — сгенерированный клиент `Api.ts` и его экземпляр `index.ts`
- `src/modules/` — модель `Solution`, mock-данные, фильтр, пути к файлам по умолчанию
- `src/solutions.css` — стили приложения
- `scripts/generate-api.mjs` — кодогенерация
- `solutions-lab6.mdj` — диаграммы StarUML (в том числе диаграмма прецедентов интерфейса React)
- `public/media/` — картинки и видео mock-растворов, `public/img/` — иконка лайка и файлы по умолчанию
